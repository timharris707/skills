## 2. Per-question rulings (Q1–Q9)

**Q1 — CAUTION.** The single proposal→merge shape and the ≥2-usable floor are right and well-precedented. But "the conductor cross-asserts completeness (every proposal accounted for)" is **not mechanizable as worded** — there is no chair-emitted mapping to check, so the conductor is *trusting* the chair to merge honestly, the exact thing §11 forbids ("completeness checks … conductor-computed and never model-trusted"). The fix is not new invention: `reconcile_edits` (INV-1) already does this for revision. Require the chair to emit an explicit mapping — each merged criterion → the proposal-id(s) it subsumes; each dropped proposal-id → reason — and have the conductor verify the **partition mechanically**: every proposal-id appears exactly once across (subsumed ∪ dropped) [coverage / no omission] and every merged criterion cites only real proposal-ids [no phantom / no invention]. Trade-off: one cheap conductor check versus a §11 violation at the feature's central new trust surface.

**Q2 — CAUTION.** Strawman (a)'s wording — "reuse the synthesizer-selection rules verbatim … as `choose_revision_seat` already did" — conflates two *different* selection axes and picks the wrong one. `choose_synthesizer_seat` keys on **provider name** (`by_name = {s.name: s …}`, synthesizer.py:220; `s.name` is the provider, resolve_board:371), so on a legitimate duplicate-provider board (`claude` + `claude#2`) the dict silently collapses to the last same-named seat and `--synthesizer-seat claude` cannot disambiguate — there is no `resolve_synthesizer_seat_id` front door. `choose_revision_seat` uses the **unique-id axis** (`by_id` first, revision.py:280–283) behind `resolve_revision_seat_id`, which *refuses* an ambiguous provider name (config.py:432). Mirror the **revision** path (a `resolve_chair_seat_id` + id-first `choose_chair_seat`), not the synthesizer's. Scoring-as-acceptance is correct (no extra endorse fan-out); add codex's criterion-scoped `RUBRIC-NOTE cN:`. Trade-off: a few lines of id-resolver reuse now versus a latent wrong-chair selection on aliased boards.

**Q3 — SHIP.** Coexistence (b) is the only viable path; I converge with gemini here. Scores are additive structure that leaves the token chain (gate, convergence, synthesizer, schema) untouched, versus a score-only fork that would double every downstream mode and make rubric runs incomparable with all prior runs. 1–5 integers (coarse, moots the epsilon question), conductor-assigned `c1…cN` at merge, `SCORE cN:` lines each hardened by `parse_verdict`'s per-line discipline. All correct.

**Q4 — SHIP, with one addition.** Informational-only at the gate for v1.15 is right — a gameable number must not move a gate (the `confidence` precedent), and no calibration data exists to tune bands against. But surface the token↔band contradiction in the **primary verdict summary**, not only deep in the scorecard, or the "auditable against stated standards" promise reads hollow exactly when it matters. Record (b) — the ABSTAIN-consistency check — as the explicit next milestone once real scored runs calibrate the bands. The "no teeth" worry is overstated: scores *do* bite through convergence (Q6), just not through the gate. Trade-off: honest-but-non-gating now versus an un-calibrated threshold formula (false precision, §11).

**Q5 — CAUTION.** Separate artifact of record: yes. But **split it in two** — `rubric.json` (criteria, weights, `proposed_by[]`, drops-with-reason, merge provenance) written at **chair-merge time** (post-consent per RH-1, *before* the opinion rounds), and `scorecard.json` (per-round scores, notes, conductor-computed totals/bands) written after. The split is forced by the pipeline's temporal shape, not aesthetics: artifacts are write-once and sha-pinned, yet the rubric must be persisted *before* the rounds it is injected into and must **survive a later scoring failure** (Q9's protect-produced-value logic) — a single write-once file cannot hold both merge-time criteria and post-round scores. Each mirrors `board_changes.py` discipline (unknown keys refused, model- vs tool-authored fields enumerated, strict-when-present pointer). State the **weight-sum-to-100** rule loudly: it is the **first numeric-sum invariant** in the codebase — conductor-computed, integer, reject-on-violation, test-guarded. Per-round scores (the trajectory is the convergence story): yes. Trade-off: two validators to maintain versus an artifact that cannot persist the rubric before the rounds depend on it.

**Q6 — SHIP.** Widen the one movement boolean: `verdict_shift OR new_cites OR score_changed` (convergence.py:197–209). Integer scores make any change ≥1, so the epsilon problem never arises; oscillation is bounded by `--max-rounds` exactly as token-flapping already is. One edge to specify: a criterion **absent in both rounds** is *not* movement (else a chronically-missing score blocks convergence forever); appearance, disappearance, or change of a score *is* movement. Surface which criteria are still moving in the round-done detail (`movement_detail_line`, convergence.py:238 already builds that string). Trade-off: one unified definition versus a bespoke score-convergence stop rule with new failure modes and the "agree on numbers, still flip tokens" gap.

**Q7 — SHIP.** Orthogonal boolean, recipe-recorded (it changes record-artifact shape — the `synthesize` precedent), own STAGES token, RH-1-respecting, `--from-recipe`-replayable, no hard `--synthesize` requirement. On the unpinned-scorecard tampering worry: it's consistent with existing posture — round artifacts aren't sha-pinned by the verdict either, and the strawman's own analogy ("stands alone like round artifacts do") holds. Refinement, not a blocker: if a run manifest exists, record the `rubric.json`/`scorecard.json` shas there so there's a tool-authored integrity anchor even when synthesis doesn't run. Trade-off: an unpinned-but-anchored standalone artifact versus forcing `--synthesize` purely to mint a pointer.

**Q8 — SHIP (c).** Ship `stakeholder-panel` (and optionally `investor-pitch`) as `LENS_PRESETS` entries; structured personas are a later milestone. My round-1 cost caveat is **resolved by the code**: per-seat *positional* lensing already exists (`lens = lens_overrides.get(sid) or (lenses[index] if index < len(lenses) else lenses[-1])`, resolve_board:367), and every `LENS_PRESETS` entry is already a 3-string list (constants.py:71–102) — so a three-archetype panel (CFO / end-user / compliance) genuinely ships in an afternoon on existing machinery. One documented caveat: archetypes bind to **seat order** and degrade on non-3 boards (a 4th seat repeats the last voice; a 2-seat board drops the 3rd). Don't let the preset silently imply `--rubric`; document the `--rubric --lens stakeholder-panel` combination. Trade-off: prose personas on existing rails versus a third preset axis that would pre-empt the seats' own proposal pass.

**Q9 — CAUTION (mostly ship, one refinement).** Proposal-floor refusal before any opinion round: ship — preflight-style NO-GO, nothing produced to protect. **Chair-merge failure → refuse (ii): correct, and *not* actually at odds with the codebase.** The reflex is "failure never discards **successful** work"; at chair-merge time no opinion round has run, so there is no successful work — the synthesizer degrades gracefully precisely because it fails *after* the expensive rounds. Silently degrading to a plain run delivers a different deliberation shape than the user asked for (the R4 "one voice wearing the board's name" objection). Refinement: exhaust the seat-selection fallback chain (next usable seat) before writing `rubric-rejected.json`, so one flaky CLI doesn't sink the run. Scoring lines — reconcile the retry tension codex flagged: **usability is defined by the VERDICT token, unchanged**; a missing/invalid SCORE triggers the standard completeness retry but then degrades to a *partial scorecard* (`—`, never imputed), never to an unusable seat — so the gate/convergence axis stays exactly as robust as today. Q9b carry-forward: ship (mechanical digest, §11 no-re-reasoning). Trade-off: refuse-on-chair-failure looks like it breaks the never-fail reflex, but the reflex protects produced value, of which there is none yet.

## 6. Invariants and guardrails

- **INV-R1 (merge partition, mirrors INV-1):** every proposal-id appears exactly once across (subsumed ∪ dropped); every merged criterion cites ≥1 real proposal-id; no criterion cites a non-existent id; empty-subsumption criteria rejected. Conductor checks structure, never semantics.
- **All ids conductor-minted:** proposal-ids at parse, `c1…cN` at merge. Models never mint identity.
- **INV-R2 (weight invariant):** integer weights sum to exactly 100, conductor-validated, reject-on-violation — the first numeric-sum invariant; test-guarded; no per-criterion precision beyond the weight (echo-score philosophy).
- **Chair on the unique-id axis** (`resolve_chair_seat_id`), duplicate-provider-safe.
- **Usability axis unchanged:** a reply is usable iff it carries a valid VERDICT token; scores are additive/best-effort; missing → `—`, never imputed; the gate reads only tokens.
- **D5 byte-identity:** every rubric render section whole-drops to zero bytes on a non-rubric run; the no-flags default stays byte-identical.
- **RH-1:** first disk write (`rubric.json`) only after consent.
- **Failure protects produced value:** proposal-floor and chair-merge refuse *before* rounds (nothing to protect); scoring/synth failures *after* rounds never discard them.
